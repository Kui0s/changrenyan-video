# ChatGPT × Codex｜协作与版本闭环 v1.0

## 所有阶段共用的原理

**开始前固定核心标准；制作中校准动态设计细节；独立审核后决定继续、定向返工或阻塞。**

重要区分：`SCORE_RUBRIC.md` 的**维度、权重、评分锚点、90分通过线、单项底线和硬性否决**是正式的固定评分尺；`AUDIT_CHECKLIST.md` 是为了找到和证明缺陷而持续细化的审核检查清单。增补检查项不意味着降分标准、修改权重或更改“好视频”的含义。

### 工作链路

1. **ChatGPT 创作**：研究俗语的字面/隐喻含义，区分机制、试验证据与推断；形成脚本、导演稿、主要镜头的状态变化和音画关系，附来源。
2. **独立 GPT 审稿**：检查科学事实、叙事完整、观众理解与工程可执行性；有明确证据才可放行。不得直接评分不存在的视频画面。
3. **Codex 工程基础验证**：可与步骤2并行，在授权工作区完整克隆候选上游仓库，阅读风格 kit、Demo、构建工具与许可证，重建原版影片；产出实际验证记录。
4. **用户选择唯一风格**：基于代码实际重建的 Demo/动帧决定系列画风；确认后以 commit 和核心组件集设定基线。
5. **Codex 15秒代表性样片**：优先测试角色连续表演、空间衔接、科学机制图示、相机运动、真实配音/字幕同步，不能使用几张静态素材加剪辑蒙混过关。
6. **双独立审核**：GPT 看真实视频、依据脚本与证据评估；独立 Codex 读源代码与时间轴、重新渲染抽样检查。必验维度缺证据记录 NOT VERIFIED、不得当作不适用排除；阶段分按固定权重的适用项归一化≥90；任何硬性否决不可放行。
7. **用户阶段确认**：通过后才授权完整影片。Codex 用复用的基线完成约60–68秒影片。
8. **全片独立审核**：按固定100分尺度综合打分，≥90且单项≥3.5/5且无否决项，用户决定正式发布；不通过则定向返工。
9. **记录沉淀**：经过验证的共用绘图/动画代码才进 `shared/`；单集经验与失败保留在独立 review 与 Git 历史中。

### 返工判定

- `PASS/GO_RECOMMENDED`：标准满足；下一阶段仍须用户授权。
- `REVISE/NO_GO`：定位时间码、实际表现、错误原因、负责方、最小修改、回归检查。
- `NOT_VERIFIED`：证据不足，不是假定通过，也不等于已经失败。
- `BLOCKED`：两轮围绕同类问题返工仍无实质改善，或技术/授权条件阻断；暂停盲目重试，转为路线诊断。

### 一轮交接包只需这些

**ChatGPT → Codex**：当前 approved 的脚本/导演稿版本、必要证据、目标段落、内容红线、制作验收条件。

**Codex → ChatGPT/独立审核**：上游 SHA、工作提交 SHA、MP4、关键帧和连续动作序列、构建命令/日志、风险、未通过项。

**独立审核 → Codex**：评分依据、时间码和证据、最小返工单；不得以“优化画面”“提升高级感”代替可定位问题。

### 版本规则

- 每次审核绑定一个明确的源码 commit 与视频文件哈希。
- 固定评分版本 `SCORE_RUBRIC v1.0` 不随本期成绩改变；如果有实质性修改评分尺需求，视为新制度提案，需用户显式决定，不能在当前作品审核中悄悄生效。
- 检查单新增条目可随轮次增加，注明原因、适用范围、观测证据；已审核版本保留历史记录。
- 不鼓励无必要的全片重渲染和全局风格重构；优先最小修复并做受影响范围回归。
