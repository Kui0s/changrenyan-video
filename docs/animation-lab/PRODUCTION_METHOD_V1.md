# 《常人言》视频制作方法论 V1｜从创意到成品的可验证闭环

> **状态：经上游真实源码与旧失败片交叉研究得出的执行方法；尚未由我们的一支新原创成片完整验证。**
>
> 本方法并不宣称“读完项目就具备成片水平”。只有连续完成**方案→真实风格帧→真实分镜→动画→配音→独立成片审核→用户验收**，且每一步证据可核查，才算被实际验证。
>
> 开源基线：`cth9191/animate@7e5eb56feb2dd573f890e1b7b34748af43d58263`（2026-11-08 GitHub `main` 与该提交相同）。上游官方6秒Sketchbook、项目内部60秒Cut-paper长片是两种不同成熟度的案例，**不能把它们等同成“Sketchbook已经证明能做好111秒人体科普”**。
>
> 用户的既有决定：**不再单独制作15秒样片作为视频流程门禁**。下面要求的2–4张真实风格帧、分镜板与关键转场检查，是**完整成片本身的前期设计和内部质量控制**，不是另一支成品样片。

## 一、定义“达到参考视频程度”的验收对象

不是将纸张背景、铅笔线或画面比例抄成一致，而是达到以下同时成立的结果：

- **信息结果：** 不读导演稿的普通观众第一次看完，能准确复述本集核心主张、机制关联及不确定性的边界；观众不能只记住“一群黄色点与红色框”。
- **视觉结果：** 人物/主体形态与目标语义一致；重点始终明确；画面具有真实发生的动作和状态转变；字幕不抢画面；手机尺寸可读。
- **镜头结果：** 场景转换的对象身份可追踪。变形镜头要能说出A如何变B；体内深入镜头要能说出从谁的哪个部位进入了什么结构、怎么退出。
- **声音结果：** 解说存在且符合实际语言，关键画面在相应词句时出现；音乐与音效辅助叙事，不遮挡语音。
- **工程结果：** 源码、帧输出与最终音视频一致，关键帧可重建，来源合规，没有冒用上游官方画面。
- **审核结果：** 完整真实MP4受独立视觉+科学审核、独立工程审核、用户验收；原固定`docs/SCORE_RUBRIC.md v1.0`的90分与单项/硬否决条件**不变**。文字方案90分不能转移给最终成片。

## 二、从研究得到的制造流程：九道门

| 关口/阶段 | 必须先做什么 | 本阶段最小可验收产物 | **失败就不能进入下一阶段**的事实 |
|---|---|---|---|
| **G0 事实与题目** | 研究俗语原意、科学证据、常见误解；决定本集只有哪**一句**话必须让观众记住 | 1句中心结论+证据出处+绝不能说的外推 | 主题不明确；证据无法支持影片结论；“有科学机制”但回答不了俗语问题 |
| **G1 故事选择** | 依故事内在的因果选择叙事机制：人物经历/真实过程/旅程/研究对照；构造开场问题→观众能看懂的变化→纠偏→可记住的结尾 | 分节拍表：每节“观众问题、可见事件、获得信息、进入下一节的理由” | 只有知识点列表、器官介绍或堆镜头技巧，没有观众问题 |
| **G2 能力可行性** | 将每个难镜头拆成上游已证明、已有扩展、未知能力；决定2D/2.5D/混合资产/3D可用程度 | 能力矩阵、源代码入口和**未知项的技术验证证据** | 上游没有人体能力却被默认为“套了Sketchbook就能画自然成人”；关键镜头只有口头方案 |
| **G3 真正的造型与风格** | 在正式场景代码中做**2–4张最大差异的真实全尺寸关键帧**：可信人物、全身透视、微观结构、研究信息页；与参考同屏比较 | 原码生成的PNG、参考对照、360px实际手机预览、用户对每张的明确接受/退回 | 人物不像人；微观只是长方框；参考与新片在构图、笔触、字号、重点色上明显不一致 |
| **G4 全片分镜** | 所有节拍从真实场景代码`renderFrame(t)`生成board；每个关键转场除前后帧外，检查**中间过程**与视线方向 | 全片Storyboard（每beat一张）、关键进/出镜头帧序列、音画提示与受审SHA | 单帧漂亮但两帧连接没有因果；重点镜头只靠淡入淡出；故事看图无法理解 |
| **G5 中文声音与节奏基线** | **先有可听的临时普通话音轨**（或用户提供音轨），按句/语义时间点建立timeline；在最终声音替换后更新画面，逐句字幕 | 普通话voice.wav、每句起止/关键词标记、对应镜头及字幕时间轴；真实总长满足<120s | 仍在按文字字符数硬估时码；没有中文声音却开工111秒最终渲染；字幕整幕一次性显示 |
| **G6 动画制作与内部检验** | 复用上游的世界坐标摄影机、真实形状morph、手绘描线与风格kit；原创人物/解剖需要另建可信模型和LOD，不以图层alpha遮掩；每完成一幕检查 | 可播放的连续动作、受审场景代码、镜头始末/中间时码、帧哈希、真实手机短段预览 | 主要动作实际是图形突然出现；人物关节乱；从体外到内部没有可追踪目标；一幕超长静止 |
| **G7 完整合成和工程QA** | 用Playwright逐帧渲染，FFmpeg合成，检查音视频/字幕/许可/解码；`tile`、`textcheck`、`review`作为技术证据，但不冒充艺术评分 | 完整MP4（**有实际普通话解说**）、FFprobe、整片帧数、SRT、构建日志、`phone.jpg`、每幕contact sheet、SHA256 | 音轨没有口播、文本太小、说明文字塞满全屏、黑帧/冻结问题、样片与报告绑定错误 |
| **G8 独立视频审核与用户放行** | 新上下文视觉/科学审查者**先盲看完整真实视频**再读稿和源码；另一个独立工程审查者检验复现/合规；用户最终观看 | 带SHA/分镜时间码/帧段/首次理解记录的独立审核、按固定7维90分评分、用户决定 | 仅有制作端`PASS`或文字阶段90分；独立Agent没看真实媒体；用户不接受即发布 |

**正确的循环：** 某一关失败，只修改导致失败的上游决策，再重新跑受影响的后续检查。**不能将G3形态错误当成G7字幕问题修复，也不能将G1故事结构错误交给Codex做“更华丽的镜头”补救。**

### 时间与成本优化

- 大型动画渲染成本高，越早拿实际可审的图像，损失越少；原上游明确的三个确认点（故事、风格帧、Storyboard）必须保留其作用。
- **不增加独立15秒样片。** G3/G4均来自将进入完整视频的同一套场景代码；确认过的画面继续发展为正片镜头，避免重复制作。
- Codex在G6可边做边自测，但自测不能替代独立视觉审查。对人物或复杂转场，在渲染整部片之前应提交**当前镜头的真实片段/连续帧**供独立观感确认；这是成片内部检查，不是宣传样片审核。
- 只有真实最终视频通过G8才能称成片完成。先存档，不自动上传发布。

## 三、把每幕导演稿从“程序指令”改为“观众实际看到的事情”

每个节拍必须同时回答：

1. **观众当前的问题是什么？** 例如“为什么饭后走动与血糖有关？”
2. **画面里谁做了什么具体动作？** 不是“触发肌群活跃状态”，而是“人物起身，臀和躯干跟随步态发生连续自然运动”。
3. **动作前后世界产生了什么可见差异？** 不是`anchor id unchanged`，而是“推进前还能看出是哪条胳膊/髋部，推进后新结构在该区域内展开，回来仍是同一个人”。
4. **下一镜为什么紧接它？** 以同一对象、同一视线、同一形状、真实因果或时间顺序接力，而不是随机添加`alpha`动画。
5. **不读说明，观众能说出什么？** 能说出来才算承载信息，不能靠一排技术标签强迫理解。

### 每幕记录表（Codex不得省略）

`scene_id | t0-t1 | 观众问题 | 旁白句/实际音频段 | 开始可见状态 | 具体动作/时间点 | 结束可见状态 | 主体世界坐标/视线锚点 | 画面新增信息 | 下一镜的物体接力方式 | 证据/科学限定 | 手机阅读检查 | 风险 | 审核证据路径`

**一幕内也可以细分若干“连续事件”，绝不能误以为“8幕完整视频”意味着只制作8张画面。**

## 四、视觉质量的具体方法

### A. 参考不是一个泛泛的“风格名”

- 使用原6秒`sketchbook`视频的2–4个有代表性的实际画面，记录主体占画面比例、纸张/笔触、强调色、字幕位置、描线时间、物体变形方式、镜头推进与退回。
- 新片G3人物、透明人体、细胞场景必须由真实场景源码渲染成图，使用`tools/compare.mjs`做并排参考；**只对比色板不够**，最重要的是形态成熟度、画面层次和注意力顺序。
- 原Demo中`doodleHero`是小圆点拟人角色，适合抽象故事，不证明正常成年人可由几根四边形做出。
- 不让每个画面都只有米色背景和黑线，然后宣称已匹配风格。参考是整体的手绘生命力、动作驱动、内容连贯性与信息密度。

### B. 上游能直接复用的动画语言

- **真实笔迹生成：** `gpencil`临时草稿→`gline`确定轮廓→`scribbleFill`上色，`pencilTool`跟随实际绘画轨迹，构成有因果的动作。
- **形状接力：** `BRIDGES A/B`、`kit/morph.js`的`shrink→morph→grow`，让一个物件经轮廓插值进入另一场景，用于**语义场景变换**。
- **世界坐标摄像机：** `camOf({z,p,to})`将世界点映射到指定屏幕点；`pieceCam/push/camMix`保证主要物体不无故漂移。
- **叙事色彩：** 一种强调色固定传达一种身份（原版橘色主体、黄色概念重点），不把所有文字、血管、人物四肢、器官同时涂成重点。
- **多样短节拍：** 原6秒demo是“疑惑→绘制灯泡→点亮→灯泡变太阳→场景展开”；60秒历史案例是15个分节拍、13个形状morph和1次重大硬切。**模仿的是过程而非复制灯泡太阳的内容。**
- **手绘on-2s：** 官方就是每2帧改变笔触/某些运动；不能单凭隔帧更新判技术失败。应看动作和画面事件是否自然、是否失去理解。

### C. 上游不能直接提供、必须另行验证的能力

- **写实可信成年人角色：** 需要角色形状设计、连续身体体积、行走/重心的真实运动，不可将`doodleHero`换成几根几何杆件后宣称达标。
- **全身→器官→组织→细胞的纵深：** 简单`shape morph`只能保证两对象的轮廓叙事连续，不能凭空生成正确的解剖嵌套和医学结构。需要**层级场景模型、逐级细节LOD、窗口遮罩/剖面和科学参考**；必要时换2.5D/3D/合规医学插画资产，而不是坚持纯程序几何直到失败。
- **准确中文配音与中文字幕：** 上游`tools/voice_words.py`固定`small.en`/英文语言识别；`voice.mjs`用`/[^a-z0-9]/g`规范化单词；`review.mjs`用英语空格数统计语速。**原工具的英文词级对齐与速度测试不能直接服务中文**。必须适配普通话分句/分词或字级对齐；不能用“词数=1”错判中文每句不密集。人工听、手动标定句首尾也可以作为先期可靠方案，自动化之后再升级。
- **高复杂度2分钟科普：** 上游最长具体项目案例（60秒的cut-paper）并不能为110秒Sketchbook医学片提供审美担保。复杂度超能力时应调整镜头媒介和故事重点，而不是加图层。

## 五、成片QA不能只看绿灯

上游测试分别验证不同事实，**请勿越权推断**：

| 工具/来源 | 能证明什么 | **不能证明什么** |
|---|---|---|
| `tools/build.mjs` | 代码拼接、语法基本正确、风格模块存在、外部资产约束 | 人物画得好、故事能懂 |
| `tile.mjs` | 指定帧可渲染且倒序复渲染一致、手机安全区提示 | 动作连续性、人体审美 |
| `still.mjs` / `storyboard.mjs` | 真实场景代码生成风格帧/分镜，不是另做一张PPT | 两帧之间的动态自然 |
| `review.mjs` | 抽帧、节奏、切点、镜头锚点、幅度、某些声音/文本指标 | “观众有获得感”“全人体放大真实可读” |
| `textcheck.mjs` | 抽样帧文字裁切、重叠、手机UI安全区 | 正文字号足够大、中文易读、字幕与音频匹配 |
| `voice.mjs`原版 | 英文配音音轨、词级时码与估算 | 未修改前不能正确验证中文词/字对齐 |
| FFprobe、哈希、帧数 | 码流与文件一致、帧数/音轨/版本可复现 | 成品是否好看、观众是否理解 |
| 独立真实视频审核 | 视觉、审美、观众信息理解（必须真实观看） | 不能单凭眼睛确保源码授权与精确可复现性 |

**尤其必须禁用两类“假PASS”**：
- `story arc: PASS (0/0 rules)`不算测试通过。`review.mjs`的JS`[].every()`自然返回true；零条规则必须标`NOT TESTED`而不是给叙事通过分。
- 上游`review.mjs`是**主要打印报告的诊断工具**，文本部分虽可独立以`textcheck.mjs`退出状态反映问题，但不能将`review.mjs`运行成功/返回0当“所有检查都通过”的总门禁。缺失的人工条件必须显式检验。
- 最终完成品如果只有引导音效而无中文口播，只能叫**无口播中间母版**，不得称正式版已完成。

## 六、重做而不是修补的判定

出现以下任何一种根本缺陷，应回到相应G关口，不要只在现有错误上改参数：

- **故事问题：** 脚本给观众的问题与画面主体不一致，大片时间用于有技术含量但对观众帮助不大的演示 → 回G1改故事与分镜。
- **视觉设计问题：** 人物一眼不像人、内部结构像灰框与椭圆、参考图根本比不上 → 回G3重做造型/媒介。
- **镜头语法问题：** 连续放大时没有新的真实结构、定位关系丢失、返回人物仍有大红框悬空 → 回G2/G4换镜头方法，而不是改`alpha`。
- **节奏问题：** 连续6秒无法识别新信息或长文本遮挡画面 → 回G4/G5重定音画事件。
- **技术问题：** 帧数或声音缺失、资源不可重建 → 留在G6/G7修工程。
- **审核失效：** 制作端自己宣布90分、独立Agent只看日志没看视频、用户未验收 → G8不得通过。

## 七、任务分工与复盘闭环

- **内容/导演（GPT创作端）：** 决定真问题、科学证据、可见事件与每个场景的“为何”；必须承担内容失败责任。
- **制作（Codex）：** 将批准的真实分镜与音轨做成画面；列出复用哪个上游函数、哪些是新增能力；不得靠代码测试冒充美术通过。
- **独立视觉/科学审核 Agent：** 与写稿、制作上下文隔离；**先直接看媒体**、按时间码说出第一遍看懂什么，再对照内容和科学证据；不能自用自审。
- **独立工程审核 Agent：** 不参与制作，上游归属、构建、脚本、依赖、渲染、素材许可、帧码、音轨一致性；不能替视觉Agent打审美分。
- **用户：** G1批准故事方向、G3确认风格/人物、G4确认整片分镜，G8最终成片验收与发布决定。
- **沉淀：** 每次返工记录`现象→证据帧与SHA→上游根因关口→修复→独立复查→是否可封装为今后通用模块`。没有真实复查证据的“最佳实践”只叫假设。

## 八、下一步仍需要实际验证

本文件是**经过静态源码研究的工作方法**，不能称“已经掌握高质量视频制作”。下一轮须真正执行`METHOD_PROOF_TASK.md`的形状morph能力验证与人体内视验证，并额外完成**普通话音轨时间轴适配**。只有新原创画面能够通过用户视觉要求、独立视频审查后，才可将对应能力从`UNVERIFIED`升级到`PROVEN`。
