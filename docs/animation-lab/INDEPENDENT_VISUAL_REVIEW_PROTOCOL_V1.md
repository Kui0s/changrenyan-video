# 成片独立审核协议 V1｜解决“技术测试通过但实际画面很差”

> 此协议是现有 `docs/SCORE_RUBRIC.md v1.0` 的**执行检查方法**，**不修改评分权重、90分合格线、单项分数或硬否决**。针对每支视频的实际截图/画面执行，不可只凭文字审核代替。
>
> 目的：阻止再次出现制作端宣称`STORY ARC PASS`、独立审核只读源码或评分表、用户看完整片却发现严重人物错误与镜头混乱的情形。

## 1. 必须审什么文件

- 固定SHA的**真实整片MP4**：有实际中文口播、实际画面及同步字幕。没有完整普通话声音的版本只能进行**无正式声音的中间状态检查**，不能正式按A维成片评分。
- 对应完整`scene/timeline/voice/subtitle`源码、媒体manifest、分镜和科学证据；但**这些只在第一遍盲看之后提供给视觉审核者**，以免受作者解释影响。
- 对应审稿人可重复检查的`ffprobe/sha256/contact sheet`以及原始素材版权清单。
- 审核者新上下文，对源码与制作过程没有参与。视觉/科学与工程分成不同审核人。作者的内部测试只作为候选事实，不得继承其PASS结论。

## 2. 第一遍：独立AI专家代理盲看（不能冒充真实普通观众研究）

**证据等级要分清：**
- `INDEPENDENT_AGENT_FIRST_WATCH`：一位未参与写作/制作、上下文干净的**专家AI代理**对实际MP4的首看记录。这是发现问题的专家代理证据，**不等于经过统计验证的普通观众理解**；AI可能凭专业知识猜出画面没有说清楚的东西。
- `HUMAN_VIEWER_FIRST_WATCH`：如有真实非专业受试者盲看，必须如实登记人数、背景、观看条件、独立原话与样本限制；**没有受试者就写“未做”，严禁由多个Agent假扮普通人。**
- `USER_ACCEPTANCE`：用户实际观看并做最终验收。无论此前多少AI认为通过，**用户拒收即对应媒体SHA的NO_GO**，不得把审查专家的评价当作用户批准。

### 专家代理首看：禁止先看导演解释

给独立视觉审核者：片名、目标受众、**真正完整可播放的MP4**，不预先告知已得分、作者声称的镜头意图和源码实现。审查者要记录**实际是否连续完整播放**；若只有联系表或未能读取视频，标记媒体审查`NOT VERIFIED`。

**第一次正常速度观看后，必须原样回答：**
1. 这支视频究竟在解释什么？开头提出什么问题，结尾给出什么结论？
2. 你记住了哪两个或三个**画面真正展示的动作/变化**？哪几秒开始不理解？
3. 主角是正常人物还是不可信几何拼接？它的行为在自然世界中合理吗？
4. 是否认出镜头从整个人哪个位置进入内部，又如何回到人？哪一瞬间空间关系断了？
5. 不看文字说明，你能说出某个关键镜头新增了什么理解，而不是“很多标签和点在移动”吗？
6. 中文解说是否真实存在、听得清楚、自然？字幕是否随声音逐句出现、手机上可读？

**不得使用制作者提供的“它成功表示了什么”来补全第一遍没看懂的内容。** 将第一遍回答作为审核报告不可删除的`INDEPENDENT_AGENT_FIRST_WATCH`节，注明这是专家代理评价。不得改写成“普通观众普遍能看懂”。若存在真实非专业受试者，另建`HUMAN_VIEWER_FIRST_WATCH`，不与AI混用。

## 3. 第二遍：对照导演与科学证据，逐镜定位

每幕按如下字段记录：

`scene_id | t_start-t_end | frame_start-frame_end | 首看感受 | 实际看到了什么 | 导演承诺什么 | 科学准确性或误导 | 画面阅读负担 | 根因 | 建议返工阶段(G1/G2/G3/G4/G5/G6/G7) | 重看证据路径 | 确认状态`

关键镜头需要展示**进入前、进入中、内部已展开、退回中、退回后**的连续视频和帧号，不允许只拿头尾两帧证明“镜头完成”。

特别检查：

- **人物结构：** 头颈、肩、胸腰、骨盆、四肢和脚掌是否从动作中真实连贯；有没有长条躯干、剪刀腿、手臂穿骨盆、支撑脚漂移。
- **内部空间：** 能不能认出某血管属于哪个器官/肌肉；血管壁、组织间隙、肌细胞膜是否两道不同屏障；不让红椭圆、黑框、黄点同时遮挡。
- **镜头规则：** 形状morph的接力对象可辨；局部放大每层有新信息；退镜回到同一个人的相同部位，不靠多个独立画布淡变造假。
- **画面主次：** 任何时刻主体只有一个，次要信息退后。科学机制由真实动作说明，不通过密密麻麻的文字“讲出来”。
- **时间与声音：** 说到哪层，画面是否正好展示那层；中文口播是否存在；不会念半句就完成大批细胞转场，也不会出现长时间无价值停滞。
- **研究外推：** 实际效果表达是否仍遵守短期血糖证据和适用范围，不能只因为研究数字出现在画面上就给科学满分。

## 4. 第三遍：独立工程审核（另一Agent）

独立工程审核者不参与制作，不替视觉审核者下美术通过结论。核查：

- 上游工具与`SKILL.md`固定SHA、改动diff、MIT许可和新素材/字体/配音权属。
- `build→renderFrame→PNG→FFmpeg→MP4`版本一致；各场景`git sha/media sha256`对齐，过程可重建。
- `tile.mjs`多帧/倒序确定性、`framehash.mjs`未改部分稳定、`textcheck`文本几何、`review`的切点/音频等实测值。
- `story arc PASS (0/0 rules)`必须**报告为未检验**；确认`review.mjs`的warn/fail有没有真的反映到门禁，而不是仅命令返回0就PASS。
- **中文工具链**：不能用英文`small.en`或`[^a-z0-9]`配音对齐、不能用空格数计算中文语速；应检查听感、每句/关键词起止真实时间及字幕对齐。
- 最终MP4含真实完整中文声音吗？如果没有，不能标为完整成片。

## 5. 报告、计分与门禁

- 先写**原始问题与证据**，后写分数；评分不是用来遮掩严重缺陷的。
- 对真实成片按旧固定`F25/C20/V15/M15/S10/A5/T10`，总分≥90、适用单维≥3.5、无硬否决；审核版本`docs/SCORE_RUBRIC.md v1.0`保持不变。
- 对尚未制作出来的角色、声音、细胞镜头不能编造实际S/A/T通过分数，只能标记阶段外或**NOT VERIFIED**，不能把已经应该审核的缺陷当N/A跳过。
- 独立审核给出`PASS / REVISE / NOT VERIFIED`，附每一缺陷精确时间段/帧范围/首看误解/修订建议；必要证据缺失就不得PASS。
- 用户**最终拒收**后应立即将成片标注`USER REJECTED / RELEASE NO_GO`；以后独立实验通过也不自动撤销过去对该媒体SHA的拒收。**没有用户明确验收不得自动发布。AI专家盲看即使满分也不能推导真实普通观众已经验证过理解。**
- 工程PASS是必要条件，视觉PASS也是必要条件；任一失败不能被另一项高分补偿；未取得用户明确同意不得发布。

## 6. 返工处理逻辑

例如：41–78秒红椭圆和图框乱叠，不能只要求Codex调`alpha`。应回到**G2技术能力或G4分镜空间设计**，将正确的层级图实际画出来，经盲看后再继续。

例如：人物像杆件但脚掌测试绿灯，回到**G3造型设计**，直接换角色的轮廓方法、形体资产与绘画技法，不能在坐标层继续强求`IK PASS`。

例如：全片没有普通话解说却把小字放底部，回到**G5语音/字幕时序**，不接受`TEXT PASS`和音效作为替代。

例如：科普事实无误但观众说不清“饭后走路究竟有什么实际意义”，回到**G1故事**重新组织，不能只提高动画精致程度。

## 7. 输出存档建议

`episodes/<EP>/reviews/FINAL_VISUAL_Rxx.md`（必须含`INDEPENDENT_AGENT_FIRST_WATCH`）、`FINAL_ENGINEERING_Rxx.md`、`USER_ACCEPTANCE_Rxx.md`分别记录；若有真实非专业受试者再另存`HUMAN_VIEWER_FIRST_WATCH`及匿名数据与有限样本说明；绑定固定代码SHA、音视频SHA和来源，前一轮不覆盖。新一轮作者修改之后不继承上一媒体的分数。

**审核永远不能代替制作前真实关键帧的视觉确认；制作前G3/G4把错误减少，最终G8再独立验收。** 两者同时存在才是可持续的视频生产方法。
